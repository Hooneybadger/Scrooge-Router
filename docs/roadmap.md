# 로드맵과 확장 지점

대회 과제에서 출발했지만 풀고 있는 문제는 그보다 넓습니다. 비용 한도가 있고
모델 선택지가 여럿일 때 무엇을 어디에 보낼지 정하는 문제는 대회가 끝나도
남습니다. 이 문서는 다른 상황에 가져다 쓰려는 사람을 위한 안내입니다.

## 어디를 바꾸면 되나

네 계층은 서로의 내부를 모릅니다. 한 층만 갈아 끼울 수 있습니다.

### 비용 예측을 바꾸고 싶다면

`cost_calibrated_router`의 `predict_episode`가 프롬프트 하나에 대해
`(정확도 향상, (싼 모델 비용, 비싼 모델 비용))`을 돌려줍니다. 같은 형태를
돌려주는 함수로 바꾸면 위 두 계층은 그대로 동작합니다.

토큰 수를 예측한 뒤 단가를 곱하는 지금 방식 대신 실제 사용량 로그를 쓰거나,
캐시 적중률을 반영하고 싶을 때 손댈 자리입니다.

### 모델 선택 기준을 바꾸고 싶다면

같은 모듈의 품질 예측이 "비싼 모델로 올렸을 때 오르는 정답 확률" 하나만
내놓습니다. 지연 시간이나 사용자 만족도처럼 다른 목표를 함께 보려면 이
값을 다목적 점수로 바꾸고, 배분기가 쓰는 정렬 기준을 같이 조정하면 됩니다.

### 예산을 커밋하는 방식을 바꾸고 싶다면

`feasibility_ladder`의 `select_fast_balanced`가 예측 목록과 상한을 받아
선택을 돌려줍니다. 순위 보정, 폭주 가드, 상향 개수 상한이 여기 모여
있습니다. 배치 단위가 아니라 스트리밍으로 들어오는 상황이라면 이 함수를
온라인 알고리즘으로 바꾸는 것이 출발점입니다.

### 위험을 값매기는 기준을 바꾸고 싶다면

`family_guard_router`의 `prompt_family_text`가 프롬프트를 묶음으로 나누고,
아티팩트의 배수가 각 묶음의 회계 비용을 정합니다. 배수는 JSON에 있으므로
코드를 고치지 않고 조정할 수 있습니다. 묶음 기준 자체를 바꾸려면 함수를
갈아 끼우고 실험 파이프라인에서 배수를 다시 고르면 됩니다.

### Premium에서 세 번째 모델을 고르는 방식을 바꾸고 싶다면

`budget_brake_router`의 승격 루프가 예측 품질 순서와 배치 예측 비율
브레이크만 봅니다. 개수 상한이나 제외 계열은 아티팩트에 있으므로 코드를
고치지 않고 바꿀 수 있습니다. Fast와 Balanced는 이 계층을 거치지 않습니다.

## 다른 모델 목록에 적용하기

지금 구현은 모델 세 개를 전제로 합니다. 싼 모델과 비싼 모델의 쌍에 대해
"올릴 가치가 있는가"를 판단하는 구조입니다.

모델이 넷 이상이면 배분기를 사다리에서 계단으로 확장해야 합니다. 인접한
두 단계씩 쌍으로 보고 순차적으로 올리는 방식이 가장 적은 수정으로 가능한
경로입니다. 모델 목록과 단가는
[`configs/routing-policy.v1.json`](../configs/routing-policy.v1.json)에
분리되어 있습니다.

## 앞으로 하고 싶은 것

### 가까운 것

- **모델 선택 정확도.** 같은 비용을 쓰면서 매번 최선을 고르는 가상의
  라우터와 8.6%p 차이가 납니다. 지금 가장 큰 개선 여지입니다
  ([#21](https://github.com/Hooneybadger/Scrooge-Router/issues/21)).
- **Python 3.13 지원.** 지금 CI는 3.9와 3.11에서 돌립니다
  ([#20](https://github.com/Hooneybadger/Scrooge-Router/issues/20)).
- **계열 분류기 개선.** 잔여 묶음이 클수록 예산을 더 잠급니다. 묶음을 더
  잘 나누면 가드를 덜 걸고도 같은 안전을 얻습니다. 배치 구성 조건을 더
  붙이지 않고 문항별 비용 오차를 줄이는 방향을 우선합니다.

### 조금 먼 것

- **모델 넷 이상 지원.** 위에 적은 계단 확장.
- **온라인 배분.** 배치 전체를 한 번에 보지 않고 요청이 들어오는 대로
  결정해야 하는 상황.
- **라이브러리로 분리.** 지금은 대회 하네스와 한 저장소에 있습니다. 배분기와
  스트레스 검사를 독립 패키지로 떼면 다른 프로젝트에서 쓰기 쉬워집니다.
