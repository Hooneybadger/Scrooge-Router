# 로드맵과 확장 지점

대회 과제에서 출발했지만 풀고 있는 문제는 그보다 넓습니다. 비용 한도가 있고
모델 선택지가 여럿일 때 무엇을 어디에 보낼지 정하는 문제는 대회가 끝나도
남습니다. 이 문서는 다른 상황에 가져다 쓰려는 사람을 위한 안내입니다.

## 어디를 바꾸면 되나

제출 라우터는 `distributional_router` 하나입니다. 아래는 그 안에서 손댈 자리입니다.

### 비용 예측을 바꾸고 싶다면

모델별 비용 평균 헤드와 상단 헤드가 프롬프트 특징을 받아 양수 비용을
돌려줍니다. 같은 형태로 바꾸면 배분기는 그대로입니다. 계열 보정 배수는
아티팩트에 있으므로 코드를 고치지 않고 조정할 수 있습니다.

토큰 수를 예측한 뒤 단가를 곱하는 대신 실제 사용량 로그를 쓰거나, 캐시
적중률을 반영하고 싶을 때 손댈 자리입니다.

### 모델 선택 기준을 바꾸고 싶다면

품질 헤드가 모델마다 정답 확률을 내놓습니다. 지연 시간이나 사용자
만족도처럼 다른 목표를 함께 보려면 이 값을 다목적 점수로 바꾸고,
배분기가 오목 껍질을 만들 때 쓰는 이득도 같이 조정하면 됩니다.

### 예산을 커밋하는 방식을 바꾸고 싶다면

오목 접두 대기열이 예측 목록과 사용 비율을 받아 선택을 돌려줍니다.
같은 내용 묶음, 이득 대비 비용 정렬, 한도 검사가 여기 모여 있습니다.
배치 단위가 아니라 스트리밍으로 들어오는 상황이라면 이 함수를 온라인
알고리즘으로 바꾸는 것이 출발점입니다.

### 위험을 값매기는 기준을 바꾸고 싶다면

구성 편이 패널티와 Fast/Balanced 위험 헤드, 내용 종류 하한이 사용
비율을 정합니다. 상한은 JSON에 있으므로 코드를 고치지 않고 조정할 수
있습니다. 배치 요약 자체를 바꾸려면 위험 특징을 갈아 끼우고 실험
파이프라인에서 헤드를 다시 고르면 됩니다.

### Premium에서 세 번째 모델을 고르는 방식을 바꾸고 싶다면

think 모델은 내용이 600종류 이상이고 구성 편이가 작을 때만 후보에
들어갑니다. 그 두 문턱은 아티팩트에 있습니다. Fast는 이 모델을 후보에서
빼므로 같은 값이 Fast 선택을 바꾸지 않습니다.

## 다른 모델 목록에 적용하기

지금 구현은 모델 세 개를 전제로 합니다. 싼 모델에서 시작해 인접한
단계로만 올리는 오목 경로입니다.

모델이 넷 이상이면 경로의 후보 행동을 늘리면 됩니다. 모델 목록과 단가는
[`configs/routing-policy.v1.json`](../configs/routing-policy.v1.json)에
분리되어 있습니다.

## 앞으로 하고 싶은 것

### 가까운 것

- **Python 3.13 지원.** 지금 CI는 3.9와 3.11에서 돌립니다
  ([#20](https://github.com/Hooneybadger/Scrooge-Router/issues/20)).
- **작은 배치.** 내용이 1~127종류이면 Light 아래쪽 비용과 계열 상단
  보정으로 일부만 올립니다.
  128종류 이상은 기존 경로입니다. 일반 배치에 q95 비용 보정을 묶는 안은
  공개 점수 손실이 커서 [#39](https://github.com/Hooneybadger/Scrooge-Router/issues/39)에서
  넣지 않기로 했습니다.

### 조금 먼 것

- **모델 넷 이상 지원.** 위에 적은 경로 확장.
- **온라인 배분.** 배치 전체를 한 번에 보지 않고 요청이 들어오는 대로
  결정해야 하는 상황.
- **라이브러리로 분리.** 지금은 대회 하네스와 한 저장소에 있습니다. 배분기와
  스트레스 검사를 독립 패키지로 떼면 다른 프로젝트에서 쓰기 쉬워집니다.

## 기여하기 좋은 곳

`good first issue`와 `help wanted` 라벨을 보시면 됩니다. 실험을 제안하실
때는 돌리기 전에 어떤 결과면 채택하고 어떤 결과면 접을지 함께 적어
주세요. 이유는 [설계 결정 기록](decisions.md)의 7항에 적었습니다.
